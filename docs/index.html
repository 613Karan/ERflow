Clinical Decision Support

ERflow

A two-stage decision support prototype for Emergency Department patient prioritization. It assesses each incoming patient, explains the result, and keeps the waiting room ordered by clinical priority — without replacing clinical judgment.

What it does

Two stages, each addressing a distinct failure mode in ED triage.

Stage 1

Patient intake & assessment

Returns the final ESI level, risk probability, a tree-level confidence score, the safety rules that fired, SHAP feature contributions and a grounded clinical narrative — with a mandatory review gate for low-confidence cases.

Stage 2

Queue scheduler

A continuously re-scored priority queue. Scores rise with waiting time, so a lower-acuity patient is never starved indefinitely, and every clinician override is written to an audit log.

Design principles

Why the system is built the way it is.

Asymmetric risk optimization. Missing a critical case is far worse than over-prioritizing a minor one. Three age-specific XGBoost models are trained with an asymmetric loss that weights false negatives heavily (α = 23.0 geriatric, 18.0 adult, 28.0 pediatric; β = 1.0).

Deterministic safety floors. Model output is bounded by ESI v5 rule checks. Priority can only be escalated automatically, never downgraded without clinician action:

Final_ESI = min(ML_ESI_Recommendation, ABCDE_ESI_Floor)

Time-aware prioritization. Queue position is recomputed continuously:

Priority(t) = 1000 · (6 − ESI_final) + 100 · P_risk + 15 · ln(1 + t_wait / 30)

Zero-history resilience. Built for realistic conditions, where roughly half of arriving patients have no verified medical history.

Grounded explanations. The narrative engine may only restate facts the models and rules already produced. A validator checks every claim — SHAP direction, numerical fidelity, rule citation and the acuity floor — and flags the case for human review if any check fails.

Run it locally

The hosted dashboard is the quickest look; a local clone adds the local language model.

git clone https://github.com/613Karan/ERflow.git
cd ERflow
pip install -r requirements.txt

python main.py --ui         # Streamlit dashboard
python main.py --api        # FastAPI backend, docs at /docs
python main.py --simulate   # terminal batch assessment
python main.py --test       # test suite
On the clinical narrative. Locally, Stage 1 prose can be written by a Gemma 4 model served by Ollama, entirely on your machine. A hosted deployment has no GPU, so it uses the built-in deterministic narrative engine instead. The dashboard always labels which engine produced the text, and grounding validation runs identically either way — the language model only ever explains a result the models and rules already decided.

Clinical governance

ERflow provides risk estimates, safety floors and grounded explanations to support clinicians. It keeps predictive risk insights separate from diagnosis, and clinicians retain final authority to override any acuity assignment. Every override is recorded in the Nurse Override Audit Log.

Prototype notice. ERflow is a research prototype trained on synthetic data. It is not a medical device, is not validated for clinical use, and must not inform real patient care.
